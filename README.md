# IT Service Desk

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](https://opensource.org/licenses/MIT)

Полнофункциональное веб-приложение для управления IT-инфраструктурой компании, включающее систему трекинга инцидентов, учета оборудования и аналитическую панель. Приложение разработано с использованием современного стека технологий: Flask (Python) для бэкенда и React для фронтенда.

## Особенности

- **Многоуровневая система авторизации** с тремя ролями пользователей (администратор, сотрудник поддержки, пользователь)
- **Управление инцидентами**: создание, отслеживание, назначение, изменение статуса и приоритета
- **Учет оборудования**: инвентаризация, отслеживание статуса, история обслуживания
- **Аналитическая панель**: визуализация ключевых показателей, статистика инцидентов и оборудования
- **Система уведомлений**: оповещения о новых инцидентах, изменениях статуса и приближающихся сроках
- **Генерация отчетов**: экспорт данных в различных форматах (PDF, CSV, Excel)
- **JWT аутентификация**: безопасный доступ к API
- **Адаптивный дизайн**: оптимизация для мобильных и десктопных устройств

## Технологический стек

### Backend
- **Python 3.9+**
- **Flask**: веб-фреймворк
- **Flask-RESTful**: для создания RESTful API
- **Flask-SQLAlchemy**: ORM для работы с базой данных
- **Flask-Migrate**: управление миграциями базы данных
- **Flask-CORS**: поддержка Cross-Origin Resource Sharing
- **PyJWT**: реализация JWT аутентификации
- **Bcrypt**: хеширование паролей
- **Marshmallow**: сериализация/десериализация объектов
- **Pandas & NumPy**: анализ данных и генерация отчетов
- **Celery & Redis**: фоновые задачи и кеширование
- **Flask-Mail**: отправка email-уведомлений
- **Pytest**: тестирование

### Frontend
- **React 18**: библиотека пользовательского интерфейса
- **React Router**: маршрутизация на стороне клиента
- **Axios**: HTTP-клиент
- **React Query**: управление состоянием и кеширование данных
- **Formik & Yup**: управление формами и валидация
- **Material-UI**: компоненты пользовательского интерфейса
- **Recharts**: визуализация данных
- **React Table**: работа с табличными данными
- **React Toastify**: уведомления
- **JWT Decode**: работа с JWT токенами
- **Date-fns**: манипуляции с датами

### База данных и инфраструктура
- **PostgreSQL**: реляционная база данных
- **Docker & Docker Compose**: контейнеризация и оркестрация
- **Gunicorn**: WSGI HTTP сервер для Python

## Архитектура проекта

Приложение построено на основе клиент-серверной архитектуры:

1. **Frontend (React)**: Отвечает за пользовательский интерфейс и взаимодействие с пользователем
2. **Backend (Flask)**: Реализует бизнес-логику, API и работу с базой данных
3. **База данных (PostgreSQL)**: Хранит все данные приложения

Архитектура бэкенда следует принципам чистой архитектуры:
- **Controllers**: Обрабатывают HTTP-запросы и возвращают ответы
- **Services**: Содержат бизнес-логику приложения
- **Models**: Описывают структуру данных и взаимодействие с базой данных
- **Middleware**: Обрабатывают запросы до/после основной логики (аутентификация, обработка ошибок)
- **Utils**: Вспомогательные функции и утилиты

## Начало работы

### Предварительные требования

Для запуска проекта вам потребуется:

- Docker и Docker Compose
- Node.js 16+ (для локальной разработки)
- Python 3.9+ (для локальной разработки)
- PostgreSQL (для локальной разработки без Docker)

### Установка

1. Клонируйте репозиторий:

```bash
git clone https://github.com/yourusername/it-service-desk.git
cd it-service-desk
```

2. Запустите приложение с помощью Docker Compose:

```bash
docker-compose up -d
```

Это запустит все необходимые сервисы: бэкенд, фронтенд, базу данных и Redis.

### Настройка переменных окружения

1. Создайте файл `.env` в корневой директории проекта на основе примера:

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

2. Отредактируйте файлы `.env` в соответствии с вашими настройками.

#### Пример настроек для backend/.env:

```
# Настройки приложения
FLASK_APP=app.py
FLASK_ENV=development
SECRET_KEY=your-secret-key-here
DEBUG=True

# Настройки базы данных
DATABASE_URL=postgresql://postgres:postgres@db:5432/it_service_desk
DATABASE_TEST_URL=postgresql://postgres:postgres@db:5432/it_service_desk_test

# JWT настройки
JWT_SECRET_KEY=your-jwt-secret-key
JWT_ACCESS_TOKEN_EXPIRES=86400  # 24 часа в секундах

# Настройки почты
MAIL_SERVER=smtp.gmail.com
MAIL_PORT=587
MAIL_USE_TLS=True
MAIL_USERNAME=your-email@gmail.com
MAIL_PASSWORD=your-email-password
MAIL_DEFAULT_SENDER=your-email@gmail.com

# Redis и Celery
REDIS_URL=redis://redis:6379/0
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/0
```

#### Пример настроек для frontend/.env:

```
REACT_APP_API_BASE_URL=http://localhost:5000/api
REACT_APP_AUTH_TOKEN_NAME=it_service_desk_token
```

### Запуск приложения

После успешного запуска Docker Compose, приложение будет доступно по следующим адресам:

- Frontend: http://localhost:3000
- Backend API: http://localhost:5000/api
- Swagger документация API: http://localhost:5000/api/docs

### Запуск без Docker (для разработки)

#### Backend:

```bash
cd backend
python -m venv venv
source venv/bin/activate  # На Windows: venv\Scripts\activate
pip install -r requirements.txt
flask db upgrade
flask run
```

#### Frontend:

```bash
cd frontend
npm install
npm start
```

## API документация

### Аутентификация

#### Регистрация нового пользователя

```
POST /api/auth/register
```

Тело запроса:
```json
{
  "username": "user123",
  "email": "user@example.com",
  "password": "securePassword123",
  "first_name": "John",
  "last_name": "Doe"
}
```

#### Вход в систему

```
POST /api/auth/login
```

Тело запроса:
```json
{
  "email": "user@example.com",
  "password": "securePassword123"
}
```

Ответ:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "username": "user123",
    "email": "user@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "role": "user"
  }
}
```

### Инциденты

#### Получение списка инцидентов

```
GET /api/incidents
```

Параметры запроса:
- `status` - фильтр по статусу (open, in_progress, resolved, closed)
- `priority` - фильтр по приоритету (low, medium, high, critical)
- `assigned_to` - фильтр по ID ответственного
- `start_date` - начальная дата (YYYY-MM-DD)
- `end_date` - конечная дата (YYYY-MM-DD)
- `search` - поисковый запрос

#### Создание инцидента

```
POST /api/incidents
```

Тело запроса:
```json
{
  "title": "Не работает принтер",
  "description": "Принтер HP в бухгалтерии не печатает документы",
  "priority": "medium",
  "equipment_id": 5,
  "reported_by": 2
}
```

#### Получение информации об инциденте

```
GET /api/incidents/{incident_id}
```

#### Обновление инцидента

```
PUT /api/incidents/{incident_id}
```

Тело запроса:
```json
{
  "status": "in_progress",
  "assigned_to": 3,
  "notes": "Взял в работу, выезжаю на место"
}
```

#### Удаление инцидента

```
DELETE /api/incidents/{incident_id}
```

### Оборудование

#### Получение списка оборудования

```
GET /api/equipment
```

Параметры запроса:
- `type` - фильтр по типу (computer, printer, network, etc)
- `status` - фильтр по статусу (active, maintenance, retired)
- `department` - фильтр по отделу
- `search` - поисковый запрос

#### Создание записи об оборудовании

```
POST /api/equipment
```

Тело запроса:
```json
{
  "name": "Ноутбук Dell XPS 15",
  "type": "computer",
  "serial_number": "DELL123456",
  "purchase_date": "2022-01-15",
  "warranty_end_date": "2025-01-15",
  "status": "active",
  "assigned_to": 5,
  "department": "Marketing",
  "specifications": {
    "cpu": "Intel Core i7",
    "ram": "16GB",
    "storage": "512GB SSD"
  }
}
```

#### Получение информации об оборудовании

```
GET /api/equipment/{equipment_id}
```

#### Обновление информации об оборудовании

```
PUT /api/equipment/{equipment_id}
```

#### Удаление оборудования

```
DELETE /api/equipment/{equipment_id}
```

### Аналитика и отчеты

#### Получение данных для дашборда

```
GET /api/analytics/dashboard
```

#### Получение статистики по инцидентам

```
GET /api/analytics/incidents/stats
```

Параметры запроса:
- `status` - фильтр по статусу
- `priority` - фильтр по приоритету
- `start_date` - начальная дата
- `end_date` - конечная дата
- `assigned_to` - ID ответственного

#### Получение статистики по оборудованию

```
GET /api/analytics/equipment/stats
```

Параметры запроса:
- `type` - фильтр по типу
- `status` - фильтр по статусу
- `department` - фильтр по отделу

#### Генерация отчета

```
POST /api/analytics/reports/{type}
```

Тело запроса:
```json
{

  "start_date": "2023-01-01",
  "end_date": "2023-12-31",
  "filters": {
    "status": "resolved",
    "priority": "high"

```

## Руководство пользователя

### Роли пользователей

1. **Администратор**
   - Полный доступ ко всем функциям системы
   - Управление пользователями и их ролями
   - Настройка системы
   - Доступ ко всем отчетам и аналитике

2. **Сотрудник поддержки**
   - Управление инцидентами
   - Учет оборудования
   - Доступ к базовой аналитике
   - Создание отчетов

3. **Пользователь**
   - Создание и просмотр своих инцидентов
   - Просмотр статуса оборудования, закрепленного за пользователем
   - Получение уведомлений

### Работа с инцидентами

1. **Создание инцидента**
   - Перейдите на страницу "Инциденты"
   - Нажмите кнопку "Создать инцидент"
   - Заполните форму с описанием проблемы
   - Выберите приоритет и связанное оборудование (если применимо)
   - Нажмите "Сохранить"

2. **Управление инцидентами**
   - Просмотр списка всех инцидентов на странице "Инциденты"
   - Фильтрация по статусу, приоритету, дате и ответственному
   - Изменение статуса инцидента через детальную страницу
   - Назначение ответственного сотрудника
   - Добавление комментариев и обновлений

### Работа с оборудованием

1. **Добавление оборудования**
   - Перейдите на страницу "Оборудование"
   - Нажмите кнопку "Добавить оборудование"
   - Заполните форму с информацией об устройстве
   - Укажите тип, серийный номер, дату покупки и другие параметры
   - Нажмите "Сохранить"

2. **Управление оборудованием**
   - Просмотр списка всего оборудования
   - Фильтрация по типу, статусу и отделу
   - Обновление информации о состоянии и местонахождении
   - Отслеживание истории обслуживания

### Работа с отчетами

1. **Генерация отчетов**
   - Перейдите на страницу "Отчеты"
   - Выберите тип отчета (инциденты, оборудование, пользователи)
   - Укажите период и дополнительные фильтры
   - Выберите формат (PDF, CSV, Excel)
   - Нажмите "Сгенерировать отчет"
   - Скачайте готовый отчет

2. **Аналитическая панель**
   - Просмотр ключевых показателей на главной странице
   - Графики распределения инцидентов по статусам и приоритетам
   - Статистика по типам оборудования и их состоянию
   - Тренды и сравнительный анализ

## Разработка

### Запуск тестов

#### Backend тесты

```bash
cd backend
pytest
```

Для запуска с покрытием:

```bash
pytest --cov=. --cov-report=term-missing
```

#### Frontend тесты

```bash
cd frontend
npm test
```

### Миграции базы данных

Создание новой миграции:

```bash
cd backend
flask db migrate -m "Описание изменений"
```

Применение миграций:

```bash
flask db upgrade
```

Откат миграции:

```bash
flask db downgrade
```

## Развертывание

### Настройка для продакшн

1. Измените переменные окружения в файлах `.env` для продакшн-среды:
   - Установите `FLASK_ENV=production`
   - Установите `DEBUG=False`
   - Используйте надежные секретные ключи
   - Настройте подключение к продакшн-базе данных

2. Соберите оптимизированную версию фронтенда:

```bash
cd frontend
npm run build
```

### Развертывание с помощью Docker

```bash
docker-compose -f docker-compose.prod.yml up -d
```

### Настройка NGINX (пример конфигурации)

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://frontend:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /api {
        proxy_pass http://backend:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
